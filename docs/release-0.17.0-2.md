# zig-analyzer 0.17.0-2

This release adds compiler-identity rename, analyzes files through their actual
build graph, and strengthens automatic-fix validation. It supports Zig 0.17.0
exactly and ships an x86_64 Linux archive with the matching patched compiler.

## Editor and compiler changes

- Rename follows compiler identities through aliases, pointers, method results,
  loop captures, and reflection strings. It checks every relevant compile unit
  and refuses a rename when the declaration differs between configurations.
  Locals and sessions without a compiler retain syntax-scoped rename.
- Compile units come from the project's `check` step, falling back to `install`.
  Dependency modules and generated `Options` and `WriteFile` sources resolve
  through the build graph. Modules generated by running built programs are
  reported as unavailable; the analyzer does not execute those programs.
- Compiler work runs on a debounced background worker. Foreground requests use
  current syntax, diagnostics from older document versions are discarded, and
  ordinary source saves preserve the incremental compiler session.
- Concurrent backends use ports assigned by the operating system. Startup
  failures retain bounded compiler stderr, and a watchdog handles stalled
  compiler requests.

## Rules and fixes

The catalog now contains 198 rules. Rule metadata, examples, profiles, and the
[rule reference](rules/README.md) derive from one catalog. Source modules are
organized by syntax, compiler, project, LSP, and rule responsibilities.

Catalog examples are checked by applying quick fixes and fix-all edits: results
must parse, formatted inputs must stay formatted, and repeating a rule's
fix-all must produce no further edits. Combined fixes are checked for valid
syntax. Example files also declare their expected diagnostics, and the suite
checks that every source module containing tests participates in the build.

`missing-container-deinit` requires a recognized allocating container type.
It no longer proposes nonexistent cleanup calls for fixed-storage sets such
as `std.EnumSet`, or infers heap ownership from `.empty` and `.{}` alone.

## Upgrading

The compiler protocol changes from version 5 to version 7. Install the analyzer
and backend from the same release together. For a source installation, rebuild
both with `zig build -Doptimize=fast` and `zig build backend`, then run
`zig-out/bin/zig-analyzer doctor` and restart your editor's language server.
See the [installation guide](installation.md) for archive and source setup.

The `defer-cleanup-in-loop` and `duplicate-c-import` rule IDs have been removed.
Remove their overrides from `zig-analyzer.json` and their source suppression
directives; unknown rule IDs produce configuration warnings. The modernization
profile still reports removed `@cImport` syntax through
`modernize-removed-syntax`.

## Validation

- 1,220 host tests, including rule examples, fix round trips, diagnostic
  examples, LSP exchanges, build graphs, and deterministic fuzz cases.
- 30 compiler-backed tests covering overlays, generated modules, concurrent
  backends, compiler identities, and rename across compile units.
- Formatting, debug compilation, an optimized build, and an analyzer self-check
  with zero findings over 239 Zig source files.
- A live LSP exchange through the installed executable, including hover,
  formatting, diagnostics, and clean shutdown.

The release workflow also verifies the version and backend manifest and
compiles a source file with the packaged backend from a temporary workspace.
